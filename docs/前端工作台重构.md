# 前端工作台重构 —— 对齐 ponder.ing 的科研工作台

> 目标：把 `research-copilot/frontend` 从「多页面 + Element Plus 表格」改成
> 「单页三栏工作台 + Tailwind 自绘」，视觉与交互对齐 <https://ponder.ing/zh>。
>
> 验收：`nuxi typecheck` 0 错 · `nuxi build` exit 0 · SSR 200 · 水合成功 · 键盘可折叠面板。

---

## 0. 一句话结论

**没有引入任何重型 UI 框架，24 个组件 + 1 个页面（共 25 个 `.vue`）、5 个 Pinia store，
全部 `<script setup lang="ts">`（25/25 实测）。**
视觉从 ponder.ing 抓的是**设计令牌**（配色 / 圆角 / 发丝线 / 字阶）而不是 DOM 结构，
所以它是一套自己的设计系统，不是抄来的皮。

## 1. 组件拆分思路

### 1.1 拆分的三个轴

拆分不是按「页面」切，而是按**数据归属**切。三条轴：

| 轴 | 判据 | 产物 |
|:--|:--|:--|
| **全局 vs 局部** | 这份数据跨面板被谁读？ | Pinia store（跨） / 组件内 `ref`（内） |
| **宿主 vs 内容** | 它负责「摆放」还是「呈现」？ | `components/ui/*`（宿主） / 其余（内容） |
| **SSR 能否渲染** | 它依赖 `window` / `canvas` 吗？ | 普通组件 / `*.client.vue` |

### 1.3 为什么是「单页三栏」而不是四个路由页

产品里最高频的动作是**「读原文 → 就这段提问」**。如果阅读器和对话在两个路由上，
每次追问都要跳页，回来的滚动位置、划词、选中文献全得重新建立。所以：

- **左栏文献库**常驻 → 换文献零跳转
- **中栏阅读器/图谱**共用一块地，Segmented 切换 → 「这篇在图上什么位置」一键可达
- **右栏对话/检视/写作/工具**共用一块地 → 追问时不用离开原文

四个路由页被删掉了（`pages/papers.vue`、`graph.vue`、`writing.vue`、`tools.vue`），
合并进 `pages/index.vue` 的 125 行骨架。

## 2. TS 类型拆分

**`types/api.ts`** 只放后端契约（与 `backend/app/schemas/` 一一对齐，含 `ChatRequest`、
`TaskOut`、`PaperDetail`、`Citation` 等）。

**`types/workbench.ts`**（128 行）只放**前端独有**的形态。两个文件**互不 import** ——
后端契约会独立演进，前端形态不该被它拖着重构。

| 类型 | 为什么需要它 |
|:--|:--|
| `PanelKey` / `MainView` / `WorkTab` | 把「面板身份」「主视图」「右栏标签」收成联合类型，避免字符串到处飞 |
| `PanelLayout` | `size` + `collapsed`。**折叠时保留 size** —— 展开要还原原宽度，不是回默认值 |
| `WorkbenchLayout` | 整个对象进 localStorage，一个 key 搞定布局持久化 |
| `NormRect` | 归一化矩形，x/y/w/h ∈ [0,1] |
| `ReaderSelection` | 一次划词。见 §5.2 —— 存归一化值而非像素是关键决策 |
| `ReaderTarget` | 跳转指令，**带 `nonce`**。见 §5.3 |
| `GraphConfig` | 图谱 11 个可视化参数 |
| `RetrievalScope` | 检索范围（paperIds + page + topK） |

关于 `DEFAULT_GRAPH_CONFIG`：**故意不放在 `types/`**。`types/` 只放类型、不放运行时会用到的值，
否则工具链可能把它当成有副作用的模块。默认值住在 `stores/graph.ts`（文件末尾有注释说明）。

## 3. Pinia Store：5 个，按「谁在读」切

拆分依据一句话：**一个 store = 一组会被同一批组件一起读写的状态。**
不是按「实体」切（那会得到 `paperStore` 一个巨型 store），也不是按「页面」切（现在是单页）。

| Store | 状态 | 谁在读 |
|:--|:--|:--|
| `library.ts` | `items / total / page / query / statusFilter / scopePaperIds` + 轮询器 | 左栏、状态栏、对话（拿范围） |
| `selection.ts` | `activeId / detail / chunks / page / target / selections[]` | 阅读器、检视、顶栏、对话 |
| `graph.ts` | `nodes / edges / config / selectedNodeId / analysis` | 图谱面板、节点卡 |
| `chat.ts` | `conversations / active / streaming / trace / quote` | 右栏对话、输入框 |
| `ui.ts` | `layout / health / tools / tasks` | 顶栏、状态栏、面板骨架 |

### 3.1 `library.ts` —— 检索范围是这一层最有价值的设计

```ts
// 空数组 = 全库。这个约定让"没选=全选"不用额外布尔位，
// 也避免了"全库"和"全选但实际选中0篇"两种状态打架。
const scopePaperIds = ref<string[]>([])

function inScope(id: string) {
  return scopePaperIds.value.length === 0 || scopePaperIds.value.includes(id)
}
```

配合 `pruneScope()`：文献被删/重新解析后自动踢出范围，否则范围里会留下已经不存在的 id，
检索时静默少召回——这类 bug 查起来极痛。

轮询（`startPolling` / `stopPolling` / `resumePolling`）只对「解析中/入库中」这类
**过渡态**的文献开，状态落地就停，避免常驻定时器。

### 3.2 `ui.ts` —— 布局持久化的写法

```ts
// 深度 watch 整个 layout 对象，懒到不用为每个面板写一套 setter 持久化
watch(layout, (v) => {
  if (!import.meta.client) return
  localStorage.setItem(LAYOUT_KEY, JSON.stringify(v))
}, { deep: true })
```

**踩过的坑**：这个文件一度出现过 6 份重复的 `toggleRail`（多次编辑叠出来的）。
已用脚本清理干净。教训是——**同一段逻辑反复改时，先删旧的再加新的**，不要只追加。

### 3.3 `graph.ts` —— 派生状态不冗余存储

`visibleNodes`（按最小度数过滤）、`visibleEdges`、`highlighted`（邻居集合）、
`maxInDegree / maxPageRank / maxDegree` 全是 `computed`。
节点着色、半径缩放都从这几个最大值归一出——不在 state 里存重复数据，
否则「删一个节点」要手动同步四五处。

## 4. Vue 组件：几个关键实现

### 4.1 `pages/index.vue` —— 三栏骨架

```
AppTopBar
├─ LibraryPanel        ← aside，宽度绑 ui.layout.library.size
├─ SplitHandle         ← side="left"，label="文献库宽度"
├─ ReaderPanel / GraphPanel（由 ui.layout.mainView 切换）
├─ SplitHandle         ← side="right"，label="右栏宽度"
└─ WorkPanel
AppStatusBar
```

折叠态宽度是常量 `COLLAPSED_W = 46`（实测键盘 Enter 后 `aside` 宽 = 46px ✅）。
全局快捷键：`Cmd/Ctrl+B` 折叠左栏、`Cmd/Ctrl+J` 折叠右栏、`Cmd/Ctrl+1/2` 切主视图。

### 4.2 `PdfCanvas.client.vue`（380 行）—— pdf.js 划词

```ts
// v4 的 TextLayer 是类，不是老版的 renderTextLayer()。
// 把 streamTextContent() 的**迭代器**直接喂给 textContentSource，
// 省一次全文 getTextContent() 的往返。
const layer = new TextLayer({
  textContentSource: page.streamTextContent(),
  container,
  viewport,
})
await layer.render()
```

选区转归一化矩形：`getClientRects()` 拿到的是像素，先减去画布原点再除以页面宽高，
得到 `NormRect[]`。这样**用户缩放后高亮框不会飘**。

`revealQuote()` 做空白归一化匹配 —— PDF 抽出的文本里换行/多空格与引用原文往往不一致，
直接 `indexOf` 会匹配失败。

### 4.3 `ForceGraph.client.vue` —— ECharts 按需引入

```ts
import * as echarts from 'echarts/core'
import { GraphChart } from 'echarts/charts'
import { TooltipComponent } from 'echarts/components'
import { CanvasRenderer } from 'echarts/renderers'
echarts.use([GraphChart, TooltipComponent, CanvasRenderer])
```

只要了图表 + 提示 + Canvas 渲染器，整个 echarts 从 1MB 降到几十 KB。

**高亮用 `dispatchAction` 而不是重建 option**：点节点时只派发
`highlight` / `downplay` 动作，避免整张图重新布局（力导向图重建会「跳」一下，很晃眼）。

### 4.4 `ChatTurn.vue` —— 引用角标事件委托

助手消息里的 `<span class="cite-mark" data-cite="...">` 由 markdown 渲染生成。
不在每个角标上挂 listener，而是**在消息容器上委托一次** —— 流式输出时 DOM 在不断替换，
逐个挂 listener 会漏且会泄漏。

未通过 NLI 蕴含验证的引用加 `.is-unverified` 类（视觉上警示），这是抗幻觉在 UI 上的出口。

## 5. 关键逻辑注释（最容易踩的四处）

### 5.1 Tailwind 不能拼类名 —— 所以类名集中在 `utils/ui.ts`

```ts
// ❌ 这样写 Tailwind 扫不到，生产构建会把样式 purge 掉
const cls = `bg-${tone}`

// ✅ utils/ui.ts：全部字面量
export function btnCls(tone: 'primary' | 'ghost' | 'danger', opts = {}) { /* ... */ }
```

Tailwind 是**静态扫描源码**找类名的。`bg-${tone}` 在源码里就是字面的 `bg-${tone}`，
扫不出 `bg-primary`。所以所有变体类名必须写全，集中在 `utils/ui.ts`。
这是本项目最容易在「开发环境正常、构建后样式丢失」上翻车的地方。

### 5.2 划词坐标存归一化值

存像素 → 用户一缩放高亮框就跑到别处。存 `x/y/w/h ∈ [0,1]` → 任意缩放都对得上。
代价是要在渲染时乘回当前宽高，值得。

### 5.3 跳转指令必须带 `nonce`

```ts
// 同一条引用点两次：paperId / page / quote 三个字段全没变，
// watch 前三个字段根本不会触发第二次滚动。所以每次都是新 nonce。
export interface ReaderTarget { paperId: string; page: number; quote?: string; nonce: number }
```

`openAt()` 里 `++targetSeq`。这个是「点了没反应」类 bug 的根因，不写注释下次一定踩。

### 5.4 `SplitHandle` 用 Pointer Events + Pointer Capture

```ts
// 用 pointerdown 而不是 mousedown+touchstart 两套：
// setPointerCapture 之后，鼠标拖到 iframe / 面板外也不会丢事件。
el.setPointerCapture(e.pointerId)
```

外加一点：拖拽期间 `document.body.style.userSelect = 'none'`，
否则鼠标划过文字会一路把正文选中（视觉上很难看）。

## 6. 视觉令牌（从 ponder.ing 实测抓取）

| 令牌 | 值 | 用途 |
|:--|:--|:--|
| `--color-canvas` | `#f7f7f8` | 页面底色 |
| `--color-surface` | `#ffffff` | 面板/卡片 |
| `--color-ink` | `#0f161e` | 正文墨色 |
| `--color-brand` | `#805ce5` | **唯一**强调色（紫） |
| `--color-brand-soft` | `rgb(128 92 229 / .12)` | 强调色浅底 |
| `--color-hairline` | `rgb(15 22 30 / .08)` | 8% 发丝分隔线 |
| 字体 | Inter + Noto Sans SC | 拉丁 / 中文 |
| 圆角 | 6 / 8 / 12 px | 控件 / 卡片 / 弹窗 |

**只有浅色主题** —— ponder.ing 本身不提供暗色，所以没有做 `theme` / `toggleTheme`。
Tailwind v4 没有 `tailwind.config.js`，令牌写在 `assets/css/main.css` 的 `@theme` 里。

> 注：`@tailwindcss/typography` 没用。它的默认排版是博客风格（大行距、装饰性引号），
> 与科研正文的密度要求相反，自写 `.md-body`（约 60 行）反而更短更贴。

## 9. 残留与下一步

1. **`rounded-panel` 令牌定义了但没被使用** —— 无害（Tailwind 只产出用到的工具类，这条只多一个 CSS 变量）。要么删掉，要么把 `rounded-panel` 用到卡片上。
2. **图谱参数侧栏在主栏较窄时挤压画布** —— 现在靠 `showConfig` 手动收起（工具栏滑杆图标）。若常读图谱，可考虑做成 480px 以下自动收起。
3. **`Failed to fetch` 文案太裸** —— 后端不可达时直接把 fetch 的英文错误抛给用户了。建议在 `useApi.ts` 里把网络错误映射成「后端未启动（检查 docker compose up）」。
4. **未做移动端** —— 三栏工作台假设桌面宽度 ≥ 1024px。这符合「桌面端科研系统」的定位，但如果要上 iPad，左右栏需要改成抽屉。
